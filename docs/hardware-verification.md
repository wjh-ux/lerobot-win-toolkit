# 真机验证清单

这份清单是为了把 README 里「已知限制」的三条逐项关掉。

**为什么需要它**：本工具目前只在无硬件的 Windows Server 2022 虚拟机上验证过——
环境安装、自检、命令拼装都没问题，但以下三件事必须有真实的 SO-101 机械臂和摄像头
才能确认，靠读代码和文档是验证不了的：

- 机械臂三步（`find-port` / `setup-motors` / `calibrate`）
- `lerobot-record` 的双摄配置串
- `lerobot-teleoperate` 在真实负载下的控制频率

跑完这份清单后，把结果填进最后的表格，就可以把 README 里对应的「已知限制」删掉。

---

## 前置准备

| 项 | 要求 |
|---|---|
| 主臂 / 从臂 | SO-101（或 SO-100）各一条，已 3D 打印组装完成 |
| 舵机 | 飞特 STS3215，从臂 6 个 1/345；主臂 6 个（191/345/191/147/147/147） |
| 电源 | 5V 4A，两条臂各自独立供电 |
| USB 线 | 两条 type-C 数据线（**不是**只能充电的线） |
| 摄像头 | 640×480 USB 摄像头 1-2 个 |
| 环境 | 已跑过 `[1]` 软件自检，全部 PASS |

**接线注意**

- 一条臂 = 一个串口。两条臂同时插，会有两个 `COMx`，别搞混。
- 先只插**一条**臂做 `setup-motors`，另一条拔掉，避免误设 ID。
- Windows 上如果串口打不开，先看设备管理器里有没有黄色感叹号（多半是 CH340/CP210x 驱动没装）。

## 步骤 1：找串口

```
菜单 [2]  或  lerobot-find-port
```

按提示：先都插好 → 脚本列出所有端口 → 拔掉你想识别的那条 → 回车。

**记录**

- [ ] 从臂串口：`COM____`
- [ ] 主臂串口：`COM____`

> 判断依据：拔掉哪条，消失的那个就是哪条。**别靠 USB 插入顺序猜**，Windows 分配是随机复用的。

---

## 步骤 2：设置电机 ID（只做一次）

```
菜单 [3]  或  lerobot-setup-motors --robot.type=so101_follower --robot.port=COM___
```

这一步把 ID 写进舵机的 EEPROM，以后不会丢，**只需做一次**。

**关键操作**

- 每次只接**一个**舵机到控制板，电机之间**不要串接**
- 顺序是从 `gripper`(6) 开始倒数到 `shoulder_pan`(1)
- 每个电机接好再按回车

**记录**

- [ ] 从臂 6 个电机全部设置成功，输出末尾是 `'shoulder_pan' motor id set to 1`
- [ ] 主臂同样完成（`--teleop.type=so101_leader`）

**常见问题**

| 现象 | 原因 |
|---|---|
| `no motor found` | 3-pin 线没插好，或电源没开 |
| 设到一半报错 | 板子上还接着别的电机，必须只接一个 |
| ID 设错想重来 | 可以重跑，会覆盖 |

## 步骤 3：标定（每条臂一次）

```
菜单 [4]  或  lerobot-calibrate --robot.type=so101_follower --robot.port=COM___ --robot.id=my_follower_arm
```

**关键操作**

1. 先把六个关节**摆到各自行程的正中间**，再按回车
2. 然后依次把每个关节**推满整个物理行程**
3. 中途不要松手跳关节

**记录**

- [ ] 从臂标定文件生成：`~\.cache\huggingface\lerobot\calibration\robots\so101_follower\*.json`
- [ ] 主臂标定文件生成：`...\teleoperators\so101_leader\*.json`
- [ ] 文件里 `homing_offset` 和 `range_min/range_max` 都不是默认值

> **最容易出问题的地方**：标定的角度范围要尽量贴着物理限位。范围留太宽，
> 掉电重启后手动摆臂可能超出标定区间，行为会不可预测。
> 如果发现 `range_min` / `range_max` 明显偏离预期，重新标一次。

**多台同型号臂**：靠 `--robot.id` 的名字区分文件。名字写错 = 用了别人的标定，行为会错乱。
菜单里 `[4]` `[5]` `[6]` 会列出已有 id 让你选，就是为了防这个。

## 步骤 4：遥操作（先不接摄像头）

```
菜单 [5]，机型选从臂 SO-101、主臂 SO-101
```

**要确认的**

- [ ] 转动主臂，从臂**同方向**跟随（不是反的）
- [ ] 六个关节方向都对
- [ ] 松手后从臂不乱抖

**记录控制频率**

遥操作默认 60Hz。加入摄像头后频率会掉，**一旦掉到 20Hz 以下从臂会明显发抖**。

- [ ] 无摄像头时终端显示的控制频率：`____ Hz`
- [ ] 有没有明显抖动：

**如果方向反了**

说明标定时的中位或行程没对齐，重新标定；不要试图在代码里改符号。

## 步骤 5：加摄像头

```
菜单 [c]  先确认摄像头编号
菜单 [5]  遥操作时加摄像头
```

**记录**

- [ ] 摄像头编号：环境相机 `____`，腕部相机 `____`
- [ ] 加摄像头后的控制频率：`____ Hz`
- [ ] 是否发抖：

**Windows 上的老问题**：OpenCV 多线程只能读一个摄像头，第二个可能报错。
这是 OpenCV 后端问题，不是本工具的问题。如果遇到，先用**单摄像头**跑通全流程。

## 步骤 6：录单摄像头数据集

```
菜单 [6]，先只接一个摄像头
```

- [ ] 设置 `HF_USER`（菜单会问，或提前 `setx HF_USER 你的用户名`）
- [ ] 录 10-20 回合，任务描述写清楚（例如 `put the red brick in a bowl`）
- [ ] 右方向键保存、左方向键重录、ESC 结束

**记录**

- [ ] 数据集 repo_id：`________________`
- [ ] 实际录了几回合：`____`
- [ ] 有没有出现视频编码错误：

**结束后检查**：`~/.cache/huggingface/lerobot/<你的用户名>/<数据集名>/` 下有 `meta/`、`data/`、`videos/`。

## 步骤 7：录双摄像头数据集（README 里的「未验证」项）

这一步专门验证 `--robot.cameras` 的配置串格式：

```
--robot.cameras="{ top: {type: opencv, index_or_path: 1, width: 640, height: 480, fps: 30}, wrist: {type: opencv, index_or_path: 0, width: 640, height: 480, fps: 30} }"
```

- [ ] 两个摄像头都能打开
- [ ] 数据集里能看到两路视频（`videos/` 下有两个 camera key）
- [ ] 录制过程不报错
- [ ] 控制频率：`____ Hz`

**如果失败**，把完整报错贴出来——这条正是要验证的。

## 步骤 8：回放验证

```
菜单 [9]  回放刚录的第 0 回合
```

- [ ] 从臂按录制时的轨迹动作
- [ ] 轨迹和录制时基本一致
